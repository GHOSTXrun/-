NIGHTJAR(1)Multi-Agent Trading TerminalPAPER

NAME

Nightjar — inspect what the system did, and why.

PIPELINE

discover → filter → size → execute → explain → reconcile

SIX SPECIALISTS

Scout / discovery

Watch pairs and volume. Propose a candidate, never an order.

Guard / safety

Veto failed sell checks, unverified token controls, thin liquidity and stale quotes. No pass, no position.

Sizer / risk

Recompute position size from current cash before every entry.

Trigger / execution

Reject slippage beyond policy. Model entry and exit with fees on both sides.

Scribe / audit

Keep the reason, timestamp and shared trace ID for every stage.

Ledger / accounting

Update settled cash after each close, then check the session loss stop.

OPERATING MODES

Implemented: browser-local paper replay with deterministic fixtures, risk settings, pause/resume, decision traces and exports. Each tick models a closed round trip; there are no open positions.

Not connected: live data, token scanners, wallet signing, DEX routing, unattended server execution and LLM agents. Six roles run as explicit simulator stages.

OVERNIGHT CONCEPT / UNVERIFIED SCENARIO

The story imagines $33.40 at 23:00 becoming $13,456.22 by 07:00, with 71 trades, 47 wins, 24 losses and 23 filtered tokens. These are supplied narrative figures, not verified performance or a forecast. They are excluded from the paper ledger.

INVARIANTS

01  failed safety check → no order
02  slippage above cap → reject
03  size from current cash
04  fees on entry and exit
05  loss limit → halt new trades
06  every decision has a trace

OPERATOR WORKFLOW

Configure → start paper → review → pause → export. Keys 0–5 switch pages. Closing the tab stops the simulator; reopening restores it paused. Browser storage may be unavailable or cleared; export for a durable copy.

LIVE REQUIREMENTS

Persistent backend, trusted market and safety feeds, secured signer, expiring quotes, idempotent orders, transaction confirmation and reconciliation, plus an independent kill switch.
